正式管理入口：`https://portfolio-5wie.vercel.app/admin`。管理密碼沿用搬移時本機帳號的密碼；登入階段不會從本機複製。47 個素材逐一比對 SHA-256 與私密旗標一致。

本機 `.private/portfolio.db` 保留為搬移時副本，不會自動與雲端同步。後續正式內容請從線上管理介面操作；不要把本機舊副本還原覆蓋雲端。私人連線設定存放 `.private/turso.env`，不會自動載入，也不會提交至 Git。原本的 `.private/owner-access.txt` 可能是初始密碼；若曾改密碼，請使用自己目前設定的密碼。

## 尚未連接雲端資料庫時

Vercel 未設定遠端 `DATABASE_URL` 時，前台與公開圖片讀取 `data/public-snapshot.json`。快照僅包含匯出當下設為公開的內容及其非私密圖片，不包含私密文章、獎狀或管理帳號。

此模式下，本機編輯或公開狀態變更不會自動同步正式站。每次更新需執行 `npm run db:public-snapshot`，確認內容後提交並重新部署；需要隱藏已公開內容時也必須更新快照並部署。連接遠端資料庫後，網站會改為依資料庫即時判斷權限，停用快照讀取。

管理登入頁可開啟，但正式站的登入與私人管理功能需完成下方雲端資料庫設定後才能使用。

## 開始使用

1. 在專案目錄執行 `npm run dev`，開啟 `http://localhost:3000/admin`。本次預覽使用 `http://127.0.0.1:3000/admin`。
2. 初始管理密碼存於 `.private/owner-access.txt`，沒有公開註冊入口。
3. 登入後建議先到「帳號設定」換成自己的長密碼，並把密碼存入密碼管理器，再刪除初始密碼檔。
4. 「內容管理」可搜尋、依文章／作品／經歷／獎狀分類及公開狀態篩選。
5. 點「設為私密」會即時隱藏內容；點「設為公開」需再按一次確認。相關文章、作品和經歷的狀態各自獨立。
6. 點「預覽」可在私人介面閱讀內容。私密文章的 `/blog/...` 公開網址即使本人登入也維持 404，請使用管理預覽。

## 中英文介面

登入頁與管理導覽都有「繁體中文 / English」按鈕，與前台共用語言設定。同一瀏覽器會記住選擇，重新整理、跳到其他管理頁或重新登入後仍會沿用；清除網站儲存空間後則回到預設英文。

登入、內容搜尋與篩選、公開確認、操作紀錄、私人預覽、文章草稿、素材標籤、錯誤／成功提示和密碼設定均支援兩種介面語言。頁面標題同時列出中文和英文。

介面切換不會改寫資料庫中的標題、文章內文、來源名稱或整理備註。「文章草稿」的「文章語言 / Article language」是獨立設定，切換介面時會保留已填資料及該選項；產生／儲存草稿和公開狀態仍需各自操作。

英文導覽對照：Content＝內容管理、Article drafts＝文章草稿、Account settings＝帳號設定、Make private＝設為私密、Make public＝設為公開、Owner only＝僅限本人。

## 草稿與備份

「文章草稿」沿用原本的來源整理功能，新增「儲存私密草稿」。新的草稿會寫進資料庫，預設私密；若網址名稱已存在會拒絕覆蓋。此按鈕保存文章文字，原始上傳附件不會自動歸檔。產生的封面若不是現有有效封面，使用既有預設圖片。

「匯出到 GitHub PR」是另外的手動匯出功能，會在操作前說明 GitHub 的檢視權限不受本站私密設定控制。匯出的 MDX 不會自動匯入此資料庫或改變公開狀態。

AI 整理預設關閉。只有勾選「使用 AI」才會把筆記、GitHub 來源及附件送至 OpenAI；未勾選時使用本機規則整理（若提供 GitHub 網址，仍會向 GitHub 讀取公開來源）。AI 請求設定 `store:false`，並在完成後嘗試刪除本次上傳的暫存附件；若清理失敗會顯示提醒，不能視為供應商所有系統都零留存。

來源最多 6 個 GitHub 儲存庫；附件最多 8 件、每件 3 MiB，整份表單（含筆記與附件）最多 4 MiB。支援 PNG、JPEG、WebP、PDF、Word、Markdown 與文字檔，檔名及檔案內容會驗證。這個流程尚未提供永久私人附件歸檔。

可在管理介面下載備份，或在本機執行：

```powershell
npm run db:backup
```

備份存入 `.private/backup-日期.json`，包含內容、圖片、關聯與操作紀錄，**不包含管理密碼或登入資訊**。請另存一份到自己控制的私人備份位置。`.private/` 本機資料不會隨 Git 備份。

遺失密碼時，在自己控制的電腦執行 `npm run admin:setup -- --reset`，會生成新的密碼並使既有登入失效。

## 日後上線到既有 Vercel 網站

網站保持既有 Next.js / Vercel 架構；不需改用其他網站平台。

1. 建立支援 libSQL 遠端連線的 Turso 資料庫，取得 URL 與伺服器用存取 token。URL 通常為 `libsql://...`。可以參考 [Turso TypeScript 連線文件](https://docs.turso.tech/sdk/ts/reference)。
2. **先在本機資料庫仍為預設時執行 `npm run db:backup`**，記下新備份檔路徑。
3. 建立未追蹤的 `.env.local`，填入以下值。不要使用 `NEXT_PUBLIC_` 前綴存放資料庫憑證，也不要將實際 token 寫入 Git。

```dotenv
DATABASE_URL=libsql://你的資料庫位址
DATABASE_AUTH_TOKEN=你的伺服器存取憑證
ADMIN_ORIGIN=https://portfolio-5wie.vercel.app
NEXT_PUBLIC_SITE_URL=https://portfolio-5wie.vercel.app
```

4. 在新建的空白遠端資料庫還原剛才的備份：

```powershell
npm run db:restore -- .private/backup-實際檔名.json
npm run admin:setup
```

這兩個指令會讀取 `.env.local`。還原會在單一交易中寫入資料，只接受空白內容資料庫；失敗時不留下部分匯入資料。管理帳號需另行建立，因為內容備份沒有帳號憑證。可用 `ADMIN_SETUP_PASSWORD` 環境變數自訂至少 16 字元的密碼，否則會產生密碼並保存在 `.private/owner-access.txt`。

5. 在 Vercel 的 portfolio 專案設定同樣的 `DATABASE_URL`、`DATABASE_AUTH_TOKEN`、`ADMIN_ORIGIN`、`NEXT_PUBLIC_SITE_URL`。只設於預定部署環境；避免讓預覽部署共用正式資料庫。若要在預覽網址登入，必須把該環境的 `ADMIN_ORIGIN` 設成實際網址。
6. 完成檢查再推送與部署。Vercel 本機檔案不能永久保存資料，本專案會拒絕在 Vercel 使用 `file:` 資料庫，避免重新部署後內容遺失。
7. 部署後分別測試：匿名無法進入 `/admin`、獎狀 `/media/...` 返回 404；本人登入可查看；將一篇文章設為私密後，公開文章網址及 sitemap 都不可見。
8. 若仍要使用本機資料庫，移除本機 `.env.local` 的遠端連線值，或使用本機專用環境設定；`ADMIN_ORIGIN` 要隨實際使用網址調整。

過去公開版本、第三方快取，以及 Git 已存在的歷史副本，不會因本機遷移自動消失。正式上線時需另行確認舊部署是否可存取。移除 Git 歷史屬於另外的破壞性作業，本次沒有重寫歷史。

## 權限與驗證方式

- 帳號只有一個；密碼以加鹽 scrypt 雜湊保存。新雜湊使用 `scrypt-v2`，舊雜湊在本人成功登入時自動升級，不會改變密碼。
- 登入用 HttpOnly、SameSite=Strict cookie；Vercel／HTTPS 下另設 Secure，8 小時到期。
- 登入嘗試上限記在資料庫，跨伺服器執行個體生效。15 分鐘內最多 10 次嘗試，成功登入會清除計數。
- API 的每個入口及私人內容存取層都檢查登入；寫入檢查同源請求。隱藏導覽或 robots.txt 不作為權限保護。
- 登出與密碼變更會刪除伺服器端登入紀錄；重播舊 cookie 無法存取。
- 登入綁定帳號版本，交易檢查可防止同時修改密碼時，舊密碼請求重新取得有效登入。
- 管理頁使用 nonce CSP 並禁止外站嵌入；請求有大小及格式限制，草稿標頭不執行程式，匯出路徑限於該文章的目錄。
- 公開內容使用動態查詢，私人頁及圖片禁止快取；圖片繞過 Next 圖片最佳化快取，讓權限變更可以即時生效。
- 更新使用版本號避免不同分頁互相覆蓋，狀態變更及操作紀錄在同一筆資料庫交易中完成。

驗證方式：`npm run lint`、`npm run build`、`npm run test:privacy`、`npm run test:security`。91 項整合檢查與 11 項安全單元測試通過。整合測試啟動正式模式伺服器並使用獨立測試資料庫，不修改實際私人內容。另以合成資料在真實瀏覽器驗證登入、預覽、公開／私密切換與登出。

正式站 2026-09-07 的唯讀檢查仍可取得舊獎狀圖片。本機修正尚未對正式站生效；詳見 [安全檢查報告](SECURITY_REVIEW.md)。

## 建議的下一階段優化

完整分階段清單與驗收條件見 [逐步優化清單](OPTIMIZATION_ROADMAP.md)。

1. **文章編輯與版本復原**：直接編輯既有文章、標籤與摘要，保存歷史版本，誤改時還原。
2. **自動備份**：定期備份到私人儲存空間，設定保留期與失敗通知。現階段提供手動備份及還原。
3. **Passkey 或雙重驗證**：跨裝置長期使用管理介面時，增加第二層登入保護。
4. **作品與文章關聯管理**：把同一作品的經歷、文章和圖片放在同一個管理畫面，顯示還有哪些公開引用，方便一次檢查。
5. **私人附件庫**：上傳新獎狀或 PDF、加入年份與標籤，提供預覽與原檔下載。

權限設計參考 [Next.js Authentication](https://nextjs.org/docs/app/guides/authentication) 與 [Next.js Data Security](https://nextjs.org/docs/15/app/guides/data-security)。
